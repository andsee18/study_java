===================================================
 ПАМЯТКА ПО МНОГОПОТОЧНОСТИ (То, что вылетело из головы)
===================================================

Представь, что многопоточность — это кафе, где потоки — это работники и посетители. Чтобы они не мешали друг другу, у нас есть "инструменты управления".

---------------------------------------------------
1. Semaphore (Семафор) - "Количество мест"
---------------------------------------------------
❓ Что это: Ограничитель одновременного доступа.
💡 Метафора: В кафе всего 2 туалета. Если пришло 5 человек, зайдут только 2. Остальные будут ждать в очереди. Как только кто-то выходит, заходит следующий.

✔️ Как работает:
Semaphore semaphore = new Semaphore(2); // 2 билетика (пермита)

semaphore.acquire(); // Поток просит билетик. Если их нет - поток засыпает и ждет.
try {
    // Делает работу (использует ресурс)
} finally {
    semaphore.release(); // Поток возвращает билетик! ОБЯЗАТЕЛЬНО в finally.
}


---------------------------------------------------
2. CountDownLatch (Защелка) - "Обратный отсчет"
---------------------------------------------------
❓ Что это: Одноразовый счетчик, который заставляет один поток ждать, пока другие не закончат свою работу.
💡 Метафора: Выезд с друзьями на шашлыки. Вы договорились: пока все 5 друзей не приедут на точку сбора, никто никуда не едет.

✔️ Как работает:
CountDownLatch latch = new CountDownLatch(5); // Ждем 5 событий

// Каждое "событие" (например, в разных потоках):
latch.countDown(); // Сбрасывает счетчик (5 -> 4 -> 3...)

// Поток, который всех ждет (обычно главный, main):
latch.await(); // Главный поток зависает здесь, пока счетчик не станет 0.


---------------------------------------------------
3. ReentrantLock (Лок) - "Ключ от комнаты"
---------------------------------------------------
❓ Что это: Продвинутая замена ключевому слову synchronized.
💡 Метафора: Одиночная примерочная. Ключ у тебя в руках. Ты явно закрыл дверь (lock) и явно открыл дверь (unlock), когда ушел. В отличие от synchronized, здесь ты можешь добавить условие "если заперто, то я просто уйду" (tryLock), или разбудить только конкретный поток (через Condition).

✔️ Как работает:
Lock lock = new ReentrantLock();

lock.lock(); // Блокируем дверь. Если уже занято - стоим и ждем.
try {
    // Работаем с общими переменными (например, меняем баланс)
} finally {
    lock.unlock(); // Главное правило Лока: ВСЕГДА открывай дверь в finally!!!
}


---------------------------------------------------
4. Wait / Notify и Producer-Consumer
---------------------------------------------------
❓ Что это: Способ общения между потоками. "Производитель" делает товары, "Потребитель" их берет.
💡 Метафора: Повар (producer) готовит пиццу и кладет на витрину. Официант (consumer) ждет пиццу.
- Если витрина полна, повар делает wait() (отдыхает, отпускает монитор).
- Когда официант забирает пиццу, он делает notify() (будит повара: "давай готовь еще!").

✔️ В современных реалиях для решения этой задачи чаще используют ArrayBlockingQueue, где методы put() и take() УЖЕ под капотом используют встроенные блокировки, чтобы потоки сами спали, когда очередь пуста или переполнена.

---------------------------------------------------
ГЛАВНОЕ ПРАВИЛО СИНХРОНИЗАТОРОВ:
Любые ресурсы (Lock, Semaphore) освобождаем в блоке finally. Если внутри блока try произойдет Exception и код сломается — блокировка должна быть снята, иначе приложение зависнет навсегда!
